Project: GoGCF, a mathematically correct, immutable, testable Go library for continued-fraction arithmetic in Gosper/HAKMEM style.
Current milestone: make sqrt(x) a real working unary operator on the unified strategy-based unary substrate.
Working components:
- Core public types/interfaces: GCFSource, GCF, PQTerm, RCFTerm, Rational, Bound, Range.
- Exact finite sources/evaluators: Int64, Rat64, FromSource, Take, Convergent, rational->RCF.
- Binary arithmetic: Add/Sub/Mul/Div with stepwise emission, range-driven ingest choice, exact finite fallback.
- Range model with inside/outside, open/closed endpoints, comparison, and zero-domain helpers.
- Unified unary execution: strategyUnaryGCF.
- Adapter-backed unary/diag support: unaryLFTStrategy, diagLFTStrategy.
- diagLFT and diagGCF infrastructure in place.
- sqrtStrategy implemented on strategyUnaryGCF.
- sqrt exact cases work: zero, perfect-square rationals, negative exact inputs -> ErrUndefined.
- sqrt interval propagation works for certainly nonnegative intervals with exact endpoint roots.
- sqrt uses exact rational Newton-style upper-bound refinement for non-square exact rationals.
- Public Sqrt(Int64(2)) currently emits first four terms: 1,2,2,2.
Known failures / missing major work:
- sqrt not yet pushed far enough to declare stable/trusted for general irrational progress.
- No E() or Pi() named source yet.
- No sin or tanh yet.
- No end-to-end target formula yet.
Next immediate task:
- extend sqrt(2) certified progress beyond four terms and validate stability of Newton/refinement + post-transform interaction.
Constraints / invariants:
- mathematical correctness first; no floating-point fallback in exact modes.
- immutable stepping semantics.
- red/green TDD workflow.
- named/procedural GCFSource implementations should live in a companion library using only the public API, not in core cf.
